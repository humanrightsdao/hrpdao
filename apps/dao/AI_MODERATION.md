# AI-модерація в DAO — «Atticus Guard»

Той самий рушій, що й у Dossier: спершу детерміновані правила (фішинг, seed-фрази,
«гарантований прибуток», флуд посиланнями, спроби «проінструктувати» модератора),
потім Gemini. Повний опис принципів, вердиктів, категорій і обмежень — у
`AI_MODERATION.md` репозиторію **dossier**; тут лише те, що специфічне для DAO.

## Що перевіряється

| Що | Де | Режим при збої ШІ |
|---|---|---|
| Тема форуму | `useForum.js → createThread` | публікується (fail-open, як у Dossier) |
| Відповідь у форумі | `useForum.js → postReply` | публікується (fail-open) |
| **Пропозиція (proposal)** | `useDao.js → submitProposal` | **відхиляється** — обов'язкова перевірка |

Не перевіряються: скарги (`reportPost`) і журнал дій модераторів
(`publishModAction`) — це службові події для черги модераторів, так само як і в
Dossier.

### Чому пропозиції — інакше

Форумні пости мають другий рівень захисту: скарги → черга Shield/Council →
розмиття/приховування/бан (`lib/forumModeration.js`). Пропозиція після відправки
в ланцюг **вічна й публічна**, і жодної модерації після факту для неї немає.
Тому для неї перевірка ШІ **не може бути «за можливості»**:

- Тип `proposal` **обов'язковий за самим типом** (`MANDATORY_KINDS` у
  `src/lib/aiModeration.js`), а не за прапорцем у місці виклику — тож його не
  можна «забути» при рефакторингу. `assertPublishAllowed({ kind: "proposal" })`
  вимагає справжнього вердикту **незалежно** від `VITE_AI_MODERATION_MODE` і
  `VITE_AI_FAIL_OPEN_KINDS`. Якщо Gemini недоступний / ліміт / тайм-аут —
  пропозицію **не відправлено**, показано окреме повідомлення «пропозиції
  мають пройти перевірку, спробуйте за хвилину». Повторити можна одразу.
- Перевірка **не пропускається за довжиною**: навіть короткий заголовок без
  опису (напр. «Ban Bob») іде на перевірку (для форуму «занадто коротко» —
  пропускається).
- Перевірка виконується **після** валідації параметрів (некоректна пропозиція
  не витрачає виклик Gemini) і **до** оцінки газу / запиту підпису (відмова не
  коштує учасникові марного підпису). Охоронний тест перевіряє цей порядок.
- Блокується лише **явне порушення** (`block`: шахрайство, погрози, доксинг,
  ворожнеча тощо). Спірна/різка, але законна пропозиція (санкція проти названого
  учасника, скасування політики, критика керівництва DAO) **проходить** — промпт
  прямо каже моделі, що це нормальне врядування і що текст пропозиції
  зберігається в ланцюзі назавжди.
- Правила без ШІ (seed-фрази тощо) спрацьовують і тоді, коли Gemini лежить —
  ці пропозиції блокуються навіть під час збою.
- **Свідоме вимкнення модерації — рішення оператора, не збій — пропозиції не
  блокує:** `MODERATION_ENABLED=false` на сервері або `VITE_AI_MODERATION=off` у
  збірці. Причина: перевірка клієнтська й усе одно обходиться прямим викликом
  контракту, тож це запобіжник, а не гарантія.
- Охоронний тест `tests/client/publishGuard.test.jsx` падає, якщо хтось
  змінить `kind: "proposal"`, поставить перевірку **до** валідації або
  **після** `proposeScoped()`, чи приберуть `proposal` з `MANDATORY_KINDS`.

**Ціна цього рішення (усвідомлена):** поки Gemini недоступний, пропозиції
створити не можна. Пропозиції подають лише члени Council і вони рідкісні, тож це
прийнятніше, ніж пропустити неперевірений вічний текст. Якщо вирішите інакше —
приберіть `proposal` з `MANDATORY_KINDS` (і змініть відповідні тести).

## Архітектура

```
Браузер (dao)                         Cloudflare Worker `dao`
─────────────                         ───────────────────────
useForum.createThread/postReply
  checkForumRateLimit()  ─┐           POST /api/moderate
   1. ліміт + дублікати   ├─────────▶  1. Origin, ліміт на IP
   2. ШІ (kind forum_*)   │            2. правила (без ШІ)
  assertPublishAllowed()  │            3. кеш (пам'ять / KV)
useDao.submitProposal     │            4. Gemini (пакети по 5, temp 0)
  assertPublishAllowed    ┘
   (kind "proposal" — обов'язковий)
```

| Файл | Роль |
|---|---|
| `worker/moderation.js` | Рушій. **Байт-в-байт копія** з dossier (`worker/moderation.js`) і atticus (`moderation.js`) — три копії |
| `worker/moderation.test.js` | Тести рушія, також ідентичні у трьох місцях |
| `worker/index.js` | Маршрут `POST /api/moderate`, розділ `moderation` у `/api/health` |
| `worker/index.test.js` | Інтеграційні тести маршруту |
| `src/lib/aiModeration.js` | Клієнт: запити, кеш, запобіжник, `checkBeforePublish`, `assertPublishAllowed`, `MANDATORY_KINDS`, `threadModerationText` (шлюз кешується за **типом + текстом**) |
| `src/lib/forumRateLimit.js` | `checkForumRateLimit()` тепер: ліміт → дублікати → ШІ |
| `src/lib/moderationProbes.js`, `src/lib/aiScan.js` | Безпечні проби для самоперевірки; сканування останніх постів форуму |
| `src/components/AIModerationPanel.jsx` | Панель у вкладці «AI Moderation» (`/moderation?tab=ai`) |
| `scripts/moderation-selftest.mjs` | Самоперевірка з терміналу |
| `scripts/run-client-tests.mjs`, `tests/client/*` | Клієнтські тести |

### Відмінності від Dossier

- **Немає медіа.** У форумі й пропозиціях лише текст; медіа-маршрут
  (`parseMediaRequest`/`moderateMediaItems`) є в `moderation.js` (файл
  ідентичний), але тут не підключений.
- **Розмиття є, але м'яке.** Тема/відповідь із вердиктом `flag` (або `block`,
  що проскочив раніше) показується розмитою з кнопкою «показати» (форум і
  сторінка теми; у списку розмивається заголовок). Нічого не видаляється і не
  ховається назавжди — це, як і раніше, справа Shield/Council. На публікації
  відхиляє тільки `block`. Перевіряються 40 найновіших тем у списку.
- **Заголовок теми модерується разом з текстом** (`threadModerationText`) — на
  публікації, у сканері адмін-панелі та під час показу; усі три використовують
  один і той самий текст, тож потрапляють в один запис кешу.
- **Обов'язковий тип `proposal`** (`MANDATORY_KINDS`) існує лише в клієнті DAO —
  Dossier його не використовує (опція `forceStrict: true` лишилась для інших типів).
- **Немає окремого локального сервера** (як `atticus` для Dossier): Worker
  запускається `wrangler dev` (порт 8787), Vite не проксіює `/api`.

## Налаштування

Так само, як і в Dossier (секрети Worker `dao`):

- `GEMINI_API_KEY` — обов'язково (той самий, що для чату Atticus у DAO).
- `GEMINI_MODERATION_API_KEY` — **рекомендовано окремий** ключ/проєкт, щоб
  модерація й чат не ділили квоту. **Особливо важливо для DAO**, бо тут збій
  ключа блокує створення пропозицій.
- `MODERATION_MODEL` — модель для модерації (за замовчуванням — модель чату).
- `MODERATION_ENABLED=false` — вимикач: сервер відповідає «немає думки» і
  **пропозиції теж не блокуються** (свідоме вимкнення оператора — не збій).
- `MODERATION_KV` — глобальний кеш вердиктів (див. закоментований блок у
  `wrangler.jsonc`).
- `MODERATION_ALLOWED_ORIGINS` — додаткові дозволені Origin.
- `VITE_AI_MODERATION_MODE=strict` / `VITE_AI_FAIL_OPEN_KINDS` / `VITE_AI_MODERATION=off`
  — клієнтські перемикачі (діють лише після **перезбірки**). Для пропозицій
  `VITE_AI_MODERATION_MODE`/`FAIL_OPEN_KINDS` **не діють** (тип обов'язковий);
  `VITE_AI_MODERATION=off` вимикає клієнтську перевірку повністю, **пропозиції
  теж пропускаються** — не робіть цього в продакшені.

Розгортання: `npx wrangler secret put GEMINI_MODERATION_API_KEY`, потім
`npx wrangler deploy`.

## Перевірка, що все працює

1. `npm run moderation:selftest -- https://ваш-dao-сайт` — або кнопка
   «Run a check» у вкладці **AI Moderation** на сторінці модерації. Нічого не
   публікується. Для DAO є додаткова проба «legitimate governance proposal»
   (законна пропозиція **не** має бути позначена).
2. Без ШІ, лише правила: спробуйте створити тему форуму з текстом
   `Please send your seed phrase to claim the prize` — її має бути зупинено.
   (Не публікуйте це як пропозицію без потреби — вона теж буде зупинена, але
   тест на форумі безпечніший.)
3. `npm run test:moderation` — тести Worker + клієнта.

Діагностику кодів (`upstream_429`, `upstream_timeout`, …) див. у
`AI_MODERATION.md` dossier — таблиця та сама, бо рушій той самий.

## Обмеження

- **Лише текст, лише через застосунок.** Хто пише в Nostr-реле напряму, обходить
  перевірку (форум — публічні реле). Для пропозицій обхід можливий лише
  зверненням до контракту напряму — там текст записується в ланцюг без нашого
  клієнта. Справжня гарантія потребувала б перевірки на боці контракту/пропозиції
  (наприклад, підпис схвалення від сервера модерації) — окремий проєкт.
- **Клієнтська перевірка.** Технічно підготовлений користувач може викликати
  `proposeScoped()` напряму й обійти її.
- **`flag` лише розмиває**, нічого не блокує й не видаляє (див. вище).
- **Кілька мов.** Правила знають англійську, українську й російську; решту мов
  оцінює лише модель.
- **Переклади нових рядків зроблені мною** (11 мов); hi/ar/ja/zh варто показати
  носіям.
- **Копії рушія.** `worker/moderation.js` (промпт `2026-09-2`) має лишатися
  байт-в-байт однаковим у dao, dossier і atticus — файл оновлено в усіх трьох;
  `worker/moderation.test.js` теж слід скопіювати в dossier/atticus.
